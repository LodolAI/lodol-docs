## Executions

An execution represents a single run of a workflow. Workflows are run asynchronously — you start an execution and then poll for its status.

### The Execution Object

```json
{
  "execution_id": "683b2c3d4e5f6a7b8c9d0e1f",
  "workflow_id": "665f1a2b3c4d5e6f7a8b9c0d",
  "version_id": "6683e1c4b2a9d7f0e5c3a1b2",
  "workflow_name": "Monthly Client Report",
  "status": "success",
  "started_at": "2026-01-15T10:30:00+00:00",
  "completed_at": "2026-01-15T10:30:03+00:00"
}
```

| Field | Type | Description |
| --- | --- | --- |
| `execution_id` | string | Unique identifier for this execution |
| `workflow_id` | string | The `id` of the workflow that was executed, which stays the same when the workflow is edited |
| `version_id` | string | ID of the version of the workflow that ran. It changes as the workflow is edited (see [Workflow IDs](/docs/api-reference/workflows#workflow-ids)) |
| `workflow_name` | string | Name of the workflow (included in list view) |
| `status` | string | Current status: `queued`, `running`, `success`, `failed`, `stopped` |
| `started_at` | string | ISO 8601 timestamp when execution started |
| `completed_at` | string \| null | ISO 8601 timestamp when execution finished |

### Run a Workflow

```
POST /api/v1/workflows/:id/run-async
```

Starts a workflow execution in the background. Returns immediately with an `execution_id` that you can poll via the [Get Execution](#get-an-execution) endpoint.

`:id` is the workflow's `id`, or the ID of any version of it. Either way, the workflow runs as it is now (see [Workflow IDs](/docs/api-reference/workflows#workflow-ids)).

**Required scope:** `workflows:execute`

Costs **1 credit** per execution. Returns `402 Payment Required` if the workspace has insufficient credits.

**Headers**

| Header | Required | Description |
| --- | --- | --- |
| `Idempotency-Key` | No | Prevents duplicate executions on retry (max 256 characters). Cached for 24 hours. Reusing a key for a different request, such as the same workflow with different inputs, returns `422`. |

**Request Body**

The body is optional. To give values for the [inputs](/docs/api-reference/workflows#inputs) the workflow declares, send a JSON object:

| Field | Type | Description |
| --- | --- | --- |
| `inputs` | object | Values for the workflow's inputs, by input name |

```json
{
  "inputs": {
    "client": "Acme",
    "month": "2026-05"
  }
}
```

Each value is converted to its input's declared type:

| Type | Accepts |
| --- | --- |
| `text` | Any value, as text |
| `number` | A number, or text that reads as one, such as `"21"` |
| `boolean` | `true` or `false`, or text such as `"yes"`, `"no"`, `"on"`, or `"0"` |
| `list` | A list, or comma-separated text |
| `object` | An object |

An optional input you leave out takes its default, so a workflow that declares no required inputs can be run without a body. The run is refused with `400`, before anything starts, naming the input at fault, when:

- a value names an input the workflow doesn't declare
- a required input has no value
- a value can't be converted to its input's type
- a value can't be stored with a run, such as `NaN`, `Infinity`, a whole number wider than 64 bits, or lists and objects nested more than 32 levels deep

The body itself must be a JSON object of at most 500 KB whose only field is `inputs`; anything else returns `400`. A workflow that starts from its own trigger or schedule takes no inputs, and sending it some returns `400`: run it without a body to start it listening.

**Example**

```bash
curl -X POST https://app.skipflow.com/api/v1/workflows/665f1a2b3c4d5e6f7a8b9c0d/run-async \
  -H "Authorization: Bearer sk_live_your_api_key" \
  -H "Idempotency-Key: unique-request-id-123"
```

**Example with inputs**

```bash
curl -X POST https://app.skipflow.com/api/v1/workflows/665f1a2b3c4d5e6f7a8b9c0d/run-async \
  -H "Authorization: Bearer sk_live_your_api_key" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: acme-report-2026-05" \
  -d '{"inputs": {"client": "Acme", "month": "2026-05"}}'
```

**Response (202)**

```json
{
  "execution_id": "683b2c3d4e5f6a7b8c9d0e1f",
  "workflow_id": "665f1a2b3c4d5e6f7a8b9c0d",
  "version_id": "6683e1c4b2a9d7f0e5c3a1b2",
  "status": "queued",
  "created_at": "2026-01-15T10:30:00+00:00"
}
```

**Response (400)**

```json
{
  "error": "'Monthly Client Report' needs a value for its 'client' input."
}
```

### List Executions

```
GET /api/v1/executions
```

Returns a list of executions for the workspace, with optional filtering and cursor-based pagination.

**Required scope:** `executions:read`

**Query Parameters**

| Parameter | Type | Description |
| --- | --- | --- |
| `workflow_id` | string | Only executions of this workflow, from every version of it. Takes the workflow's `id` or the ID of any of its versions |
| `limit` | integer | Max results to return (1-100, default 20) |
| `after` | string | Cursor: the `execution_id` of the last item from the previous page |

**Example**

```bash
curl "https://app.skipflow.com/api/v1/executions?workflow_id=665f1a2b3c4d5e6f7a8b9c0d&limit=10" \
  -H "Authorization: Bearer sk_live_your_api_key"
```

**Response (200)**

```json
{
  "executions": [
    {
      "execution_id": "683b2c3d4e5f6a7b8c9d0e1f",
      "workflow_id": "665f1a2b3c4d5e6f7a8b9c0d",
      "version_id": "6683e1c4b2a9d7f0e5c3a1b2",
      "workflow_name": "Monthly Client Report",
      "status": "success",
      "started_at": "2026-01-15T10:30:00+00:00",
      "completed_at": "2026-01-15T10:30:03+00:00"
    }
  ]
}
```

### Get an Execution

```
GET /api/v1/executions/:id
```

Retrieves a single execution by its ID. By default, step results are omitted to keep polling lightweight.

**Required scope:** `executions:read`

**Query Parameters**

| Parameter | Type | Description |
| --- | --- | --- |
| `include_step_results` | string | Set to `true` to include step-level results in the response |

**Example**

```bash
# Poll for status (lightweight)
curl https://app.skipflow.com/api/v1/executions/683b2c3d4e5f6a7b8c9d0e1f \
  -H "Authorization: Bearer sk_live_your_api_key"

# Fetch full results after completion
curl "https://app.skipflow.com/api/v1/executions/683b2c3d4e5f6a7b8c9d0e1f?include_step_results=true" \
  -H "Authorization: Bearer sk_live_your_api_key"
```

**Default Response (200)**

```json
{
  "execution_id": "683b2c3d4e5f6a7b8c9d0e1f",
  "workflow_id": "665f1a2b3c4d5e6f7a8b9c0d",
  "version_id": "6683e1c4b2a9d7f0e5c3a1b2",
  "status": "running",
  "started_at": "2026-01-15T10:30:00+00:00",
  "completed_at": null,
  "error": null
}
```

**Response with `include_step_results=true` (200)**

```json
{
  "execution_id": "683b2c3d4e5f6a7b8c9d0e1f",
  "workflow_id": "665f1a2b3c4d5e6f7a8b9c0d",
  "version_id": "6683e1c4b2a9d7f0e5c3a1b2",
  "status": "success",
  "started_at": "2026-01-15T10:30:00+00:00",
  "completed_at": "2026-01-15T10:30:03+00:00",
  "steps": [
    { "index": 0, "status": "completed", "result": "..." },
    { "index": 1, "status": "completed", "result": "..." }
  ],
  "error": null
}
```

### Stop an Execution

```
POST /api/v1/executions/:id/stop
```

Stops a running execution. Steps that have already completed will not be rolled back. Returns `400 Bad Request` if the execution is already in a terminal state (`success`, `failed`, or `stopped`).

**Required scope:** `workflows:execute`

**Headers**

| Header | Required | Description |
| --- | --- | --- |
| `Idempotency-Key` | No | Prevents duplicate stop requests on retry |

**Example**

```bash
curl -X POST https://app.skipflow.com/api/v1/executions/683b2c3d4e5f6a7b8c9d0e1f/stop \
  -H "Authorization: Bearer sk_live_your_api_key"
```

**Response (200)**

```json
{
  "execution_id": "683b2c3d4e5f6a7b8c9d0e1f",
  "status": "stopped"
}
```
