A Lodol **workflow** is a short list of steps that runs on its own. It starts when something happens in one of your apps, on a schedule, or when you start it, and then works through its steps the same way every time. There is no server to keep running, no script to maintain and no keys sitting in a file.

<WorkflowPreview
  title="Log Stripe payments"
  steps={[
    { step: 'New Stripe payment', app: 'Stripe', trigger: true },
    { step: 'Append row', app: 'Google Sheets', note: 'Revenue sheet' },
    { step: 'Send a message to a channel', app: 'Slack', note: '#sales' },
  ]}
  caption="A real workflow: each new Stripe payment adds a row to a sheet and posts in Slack."
/>

This one workflow replaces a script, a cron job, a server and an alert. It starts itself when a payment comes in, uses your Stripe, Google and Slack connections without ever showing their keys, records every run step by step, and emails you if a run fails. The rest of these docs build on this example.

## The parts of a workflow

| Part | What it is |
| --- | --- |
| [Trigger](/docs/concepts/triggers) | What starts the workflow: an event in an app, a schedule, or you. |
| [Steps](/docs/concepts/steps-and-data) | What it does, in order: app actions such as **Append row**, and built-in steps such as **If** or **Request approval**. |
| [Data](/docs/concepts/steps-and-data#every-step-hands-its-result-to-the-steps-after-it) | What each step produces, which later steps read with `@` references such as `@payment.amount`. |
| [Inputs and outputs](/docs/concepts/inputs-and-outputs) | Values a workflow can be given when it starts, and values it hands back. |
| [Runs](/docs/concepts/runs) | Each time the workflow runs, recorded step by step. |
| [Connections and secrets](/docs/concepts/connections) | Your app accounts and API keys, kept encrypted and used by name. |
