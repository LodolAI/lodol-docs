Each time a workflow starts, Lodol creates a **run**: one pass through the workflow from its trigger to its last step. In the Stripe example, every payment that comes in is one run.

## Every run is recorded

A run's history shows every step it took, in order: what each step did, when, and how long it took. When a run fails, the history shows the step that stopped it. Open it from the workflow, or read it with the [API](/docs/api/runs#get-a-run).

If a run fails, you get an email as soon as it does, and a notice in Lodol. Your [AI tool](/docs/build-with-ai) can read the same run, work out what went wrong and fix the workflow.

## Run statuses

| Status | What it means |
| --- | --- |
| `queued` | Started, and about to begin its first step |
| `running` | Working through its steps |
| `success` | Reached the end of the workflow |
| `failed` | A step failed and the run stopped there |
| `stopped` | Someone stopped it before it finished |

Stopping a run doesn't undo the steps it already completed: a message it sent stays sent. See [Handle failures](/docs/guides/failures) for keeping a run going when one step fails.

## Some steps wait

**Request approval** pauses a run until a person answers. The run waits without using any resources, then carries on from that step with the answer. **Wait** pauses a run for a set time, or until a date and time.

## What counts as a run

Your plan includes a number of runs each month. A run counts once, however many steps it takes, whether you started it or a trigger, a schedule or the API did. These don't count:

- a workflow that is turned on and waiting for its trigger
- a workflow that another workflow runs with a **Run a workflow** step

Runs reset on the 1st of each month (UTC). The workspace owner gets an email when 80% of the month's runs are used. If they run out, new runs pause until the 1st, unless you add more runs or turn on extra runs in **Billing**. See [pricing](https://www.lodol.com/pricing) for each plan's runs.
