## Requests per minute

Each workspace can make a set number of API requests per minute, shared by all of its keys:

| Plan | Requests per minute |
| --- | --- |
| Free | 5 |
| Builder | 50 |
| Pro | 200 |
| Enterprise | Custom |

Every response says where you stand:

| Header | What it holds |
| --- | --- |
| `X-RateLimit-Limit` | Requests allowed per minute |
| `X-RateLimit-Remaining` | Requests left in the current window |
| `X-RateLimit-Reset` | Seconds until the window resets |

Over the limit, the API returns `429 Too Many Requests` with a `Retry-After` header saying how many seconds to wait. See [Retry safely](/docs/api/errors#retry-safely).

## Runs in progress at once

Your plan also limits how many runs can be in progress at the same time, listed as **Workflows running at once** on the [pricing page](https://www.lodol.com/pricing). Starting a run while you're at the limit returns `429` with the code `concurrency_limit`. It has no `Retry-After`, since waiting a moment doesn't help: start the run once one of the others finishes.

## Runs per month

Each run you start through the API counts as one of your plan's monthly runs, the same as a run started any other way. When the month's runs are used up, starting a run returns `429` with the code `monthly_run_limit`, and its `resets_at` says when runs come back: the 1st (UTC), unless you add runs or turn on extra runs in **Billing** first. See [What counts as a run](/docs/concepts/runs#what-counts-as-a-run).

## Request size

The body of a [Run a workflow](/docs/api/runs#run-a-workflow) request can be at most 500 KB.
